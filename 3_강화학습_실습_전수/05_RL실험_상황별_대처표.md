# 3교시 상황별 대처표 (Physical AI 실습 · 120분)

> **오늘 밤 외워 갈 판단 기준.** 다루는 범위: "시뮬레이션 환경에서 **보상 함수를 직접 설계**하며 **정책 성능을 개선하는 실험** 능력", "**PyTorch 기반 구현**", "**보상 극대화, 학습 안정성을 해석**", "RRT 등 경로 탐색".
> 실제 문제 형식은 공개되지 않았다. 아래 숫자는 **원 논문에서 확인한 값** 또는 **내 실험(`code/`)에서 직접 나온 값**만 썼고, 어느 쪽인지 표시했다.
> 실습 중에는 검색으로 **공식 문서의 문법**만 확인하고, 아래 판단 순서는 머리에서 꺼내 쓴다.

## 1. 시작 10분: 무엇부터 확인하나
| 확인할 것 | 어떻게 | 왜 |
|---|---|---|
| **요구사항·평가 기준** | 문제 설명에서 "무엇을 개선하라"(리턴? 성공률? 코드 완성? 해석?)와 조건(시간·스텝 제한)을 먼저 표시 | 무엇을 "잘했다"로 보는지에 따라 할 일이 다르다 |
| **행동이 이산인지 연속인지** | `print(env.observation_space, env.action_space)` → `Discrete(n)`이면 이산, `Box(...)`면 연속 | 알고리즘 선택이 여기서 갈린다(2장) |
| **보상·종료 방식** | 무작위 행동으로 한 판 돌려 보상 합·판 길이·종료 이유(terminated / truncated) 확인 | **무작위 기준선** 점수 확보, 종료 처리 버그 예방 |
| **실행 속도** | 1,000스텝 돌리는 데 몇 초인지 잰다 | 120분 안에 몇 스텝 학습할 수 있는지 계산 |
| **제공 코드** | 이미 있는 학습 코드, 빈칸 위치, 고정된 설정 | 처음부터 짤지, 고쳐 쓸지 결정 |

## 2. 알고리즘 고르기
| 상황 | 1순위 | 이유 |
|---|---|---|
| 이산 행동 + 상태가 작은 격자 | **표 Q-learning** | 가장 빠르고 디버깅 쉬움 |
| 전이 확률 P가 주어짐 | **가치 반복·정책 반복** | 학습 없이 계산으로 최적 정책 |
| 이산 행동 + 상태가 연속값(CartPole류) | **PPO** (또는 DQN) | PPO가 설정에 덜 민감. 내 실험: PPO는 약 5만 스텝부터 500점 유지, DQN은 같은 설정에서도 시드마다 136~500점 |
| **연속 행동**(토크·속도, Pendulum·MuJoCo류) | **SAC** | 데이터 효율. 내 실험(Pendulum): SAC 약 6천 스텝, PPO 약 6만 스텝에 비슷한 성능 |
| 연속 행동인데 제공 코드가 PPO | PPO를 연속용으로 고쳐 사용 | Categorical → Normal, log_prob를 행동 차원으로 **합산**, 버퍼엔 자르기 전 행동 저장 |
| 장애물 지도에서 경로 | 격자면 **A\***, 연속 공간·고차원이면 **RRT**(짧은 경로 필요하면 **RRT\***) | A\*는 최단 보장, RRT는 빠르지만 최적 아님 |

## 3. 처음 돌릴 설정값
| | PPO | SAC | DQN |
|---|---|---|---|
| 학습률 | 3×10⁻⁴ (논문) | 3×10⁻⁴ (논문) | 1×10⁻³ (내 CartPole) |
| 할인율 γ | 0.99 (논문) | 0.99 (논문) | 0.99 |
| 데이터 | 한 번에 2048스텝 모아 **10 epoch**, 미니배치 64 (논문 MuJoCo) | 버퍼 10⁶(논문), 배치 256(논문), 처음 1,000스텝은 무작위 행동(내 실험) | 버퍼 5만, 배치 128, 처음 1,000스텝은 쌓기만(내 실험) |
| 핵심 장치 | clip ε 0.2, GAE λ 0.95 (논문) | Q 두 개 min, 타깃 Polyak τ 0.005(논문), α 자동(목표 엔트로피 = −행동 차원 수, 후속판) | 타깃망 복사 500스텝마다(내 실험, 원 논문은 1만 번 업데이트마다), ε 1.0 → 0.05를 1.5만 스텝 동안(내 실험) |
| 망 크기 | 은닉층 64×2, tanh (논문) | 은닉층 256×2, ReLU (논문) | 은닉층 128×2, ReLU (내 실험) |
| 그 밖 | 가치 손실 계수 0.5, 기울기 클리핑 0.5, 이점 정규화 (구현 관행) | 평가는 평균 행동으로 | Double DQN, Huber 손실 |

## 4. 성능이 안 오를 때 점검 순서 (한 번에 하나만 바꾼다)
1. **버그부터** — 리턴이 무작위 기준선보다 낮거나 전혀 안 움직이면:
   - done 처리: **terminated만** 미래 가치 0, truncated는 부트스트랩
   - 보상 부호, 행동 범위(연속이면 clip·tanh 스케일)
   - 연속 행동 `log_prob`를 차원별로 **합산**했는지
   - `zero_grad → backward → step` 순서, 타깃·이점에 `no_grad` / `detach`
   - SAC는 `rsample()`인지(`sample()`이면 정책이 안 배움)
2. **보상 크기**: 한 스텝 보상이 수십~수백이면 정규화(`gym.wrappers.NormalizeReward`)하거나 스케일을 줄인다. SAC 원 논문은 보상 크기에 특히 민감하다고 밝혔다.
3. **관측 정규화**: 관측값 범위가 제각각이면 `gym.wrappers.NormalizeObservation`(MuJoCo류에서 특히 중요).
4. **학습률**: 곡선이 출렁이거나 급락 → 낮춘다(예: 3×10⁻⁴ → 1×10⁻⁴). 너무 느리면 올린다.
5. **탐험**: 엔트로피가 금방 0 → PPO 엔트로피 계수↑, SAC α 자동 조절, DQN ε 감소를 늦춘다.
6. **학습량**: 가장 흔한 원인은 스텝 부족. 남은 시간 안에서 스텝을 늘린다.
7. **보상 설계**: 보상이 너무 희소하면 잠재 기반 성형(6장).
8. **시드**: 하나만 보고 판단하지 않는다(가능하면 3개 이상).

## 5. 학습 곡선·로그 증상 → 처방
| 증상 | 흔한 원인 | 처방 |
|---|---|---|
| 처음부터 전혀 안 오름 | 버그, 보상 희소, 탐험 부족 | 4장 1번 점검 → 잠재 기반 성형, 탐험↑ |
| 올랐다가 **급락** | 학습률 과다, 타깃망 없음(DQN), 업데이트 과다(PPO) | 학습률↓, 타깃망, PPO epoch↓·ε↓ |
| PPO **KL·clip 비율 급증** + 리턴 급락 | 한 번에 정책을 너무 많이 바꿈 | 학습률↓, epoch↓, ε 0.2 → 0.1, KL이 목표를 넘으면 업데이트 일찍 멈추기(구현 관행) |
| 계속 출렁임 | 분산 큰 이점 추정, 배치 작음 | GAE·기준선, 배치·롤아웃↑ |
| Q 값이 끝없이 커짐 | 과대평가, 발산 | Double DQN, Q 두 개 min, 보상 정규화 |
| 엔트로피가 금방 0 | 너무 일찍 한 행동으로 굳음 | 엔트로피 계수↑ / α 자동 조절 |
| 설계 보상은 오르는데 성공률 그대로 | **보상 해킹** | 원래 지표로 평가, 보상 다시 설계 |
| 학습 중 점수는 좋은데 평가가 나쁨 | 평가 때도 탐험 중, 정규화 통계 불일치 | 평가는 greedy / 평균 행동, 정규화 통계 고정 |
| 시드마다 결과가 크게 다름 | 강화학습 원래 편차 | 시드 여러 개 평균 ± 표준편차로 보고 |

- 내 실험 기억: DQN에서 타깃망을 끄면 시드 3개 모두 9.8점(최대 500)으로 붕괴 / 1-step Actor-Critic은 235 → 59 → 141처럼 출렁임 / PPO는 KL 0.002~0.006, clip 비율 0.02~0.10에서 안정.

## 6. "보상 함수를 설계해 성능을 높여라"가 나오면 (순서)
1. **원래 목표 지표**를 정한다: 성공률, 도착 스텝, 원래 리턴 중 무엇인가.
2. **기준선**: 원래 보상 그대로 학습 → 지표 기록.
3. **잠재 기반 성형** 추가(Wrapper로): r′ = r + γΦ(s′) − Φ(s), Φ 예: −(목표까지 거리), 끝난 상태 Φ = 0. 최적 정책을 바꾸지 않는다.
4. 필요하면 **비용·안전 항**: 에너지(−c × 행동²), 충돌 벌점. 항끼리 크기 균형.
5. **같은 스텝 수·같은 시드들**로 원래 지표를 비교(평균 ± 표준편차).
6. **해킹 확인**: 설계 보상만 오르고 원래 지표가 그대로면 실패한 설계.
7. 결과를 표 + 한 줄 해석으로 정리(9장 틀).
- 함정: 목표 근처 보너스 → 맴돌기(내 실험에서 시드 5개 모두 도착 안 함) / 매 스텝 벌점 + 실패 시 종료 → 일부러 빨리 실패 / 생존 보너스만 → 가만히 버티기.

## 7. MuJoCo류(연속 제어 로봇)가 나오면
- 환경 예: HalfCheetah, Hopper, Walker2d, Ant (gymnasium의 MuJoCo 환경). 관측은 관절 각도·속도, 행동은 관절별 힘(연속).
- **관측 정규화·보상 정규화**를 먼저 켠다.
- 행동 처리: SAC = 가우시안 + tanh + 행동 범위 스케일 / PPO = 가우시안 + 환경에 보낼 때만 clip(버퍼엔 자르기 전 값).
- 시간: PPO 논문의 MuJoCo 실험은 100만 스텝 기준 → 120분 노트북 CPU로는 부족할 수 있다. **SAC를 우선** 고려하고, 짧은 학습이라면 "개선 추세"를 곡선·수치 근거와 함께 보고한다.
- 평가: 탐험 없이(평균 행동) 여러 판 평균.

## 8. 120분 시간 배분 (예시)
| 시간 | 할 일 |
|---|---|
| 0~10분 | 요구사항·환경 확인, 무작위 기준선(1장) |
| 10~30분 | 기준 알고리즘을 짧게 한 번 돌려 코드가 도는지, 곡선 방향 확인 |
| 30~90분 | 한 번에 하나씩 개선(보상 → 정규화 → 학습률 → 탐험 → 스텝), 실험마다 설정·결과 기록 |
| 90~110분 | 가장 좋은 설정으로 최종 실행(가능하면 시드 여러 개), 탐험 없이 평가 |
| 110~120분 | 결과 표·해석 작성, 제출 확인 |

## 9. 결과 보고 틀 (답안에 그대로 쓰기)
```text
① 기준선: [알고리즘·주요 설정] → 평균 리턴 X ± Y (시드 n개, 평가 k판)
② 바꾼 것 1: [무엇을 왜] → 결과
   바꾼 것 2: [무엇을 왜] → 결과
③ 최종: [설정] → 평균 리턴 Z ± W, 원래 목표 지표(성공률 등) 
④ 해석: 왜 좋아졌나(근거: 곡선, KL·clip 비율, 엔트로피, Q 값 등)
⑤ 한계와 다음 단계: 시드 수·학습 스텝 부족 등
```

## 10. 검색으로 확인해도 되는 것 vs 외워 가야 하는 것
| 검색으로 확인 (공식 문서) | 외워 가야 함 (검색으로 대신 못 함) |
|---|---|
| `env.step` 반환값, `gym.wrappers` 이름(NormalizeObservation, NormalizeReward, ClipAction 등) | 알고리즘 구조: DQN 타깃, PPO clip + GAE, SAC 4단계(Q·정책·α·Polyak) |
| `torch.distributions.Normal` / `Categorical` 사용법, `rsample` | 4장 점검 순서, 5장 증상 → 처방 |
| `nn.utils.clip_grad_norm_`, `load_state_dict` 문법 | 6장 보상 설계 순서, 9장 보고 틀 |
| 함수 인자 이름·모양 오류 메시지 해석 | 2장 알고리즘 선택 기준 |
