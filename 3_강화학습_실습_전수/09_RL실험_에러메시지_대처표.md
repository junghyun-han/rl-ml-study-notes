# 실습 에러 메시지 대처표

> 강화학습 실습 중 자주 만나는 오류를 **일부러 내서 받은 실제 메시지**(PyTorch 2.15, gymnasium 1.4 기준)와 원인·고치는 법. 확인 코드: `code/error_messages_check.py`.
> 메시지는 첫 줄만 적었다. 버전이 다르면 문구가 조금 다를 수 있지만 핵심 단어(dtype, shapes, grad_fn 등)는 같다.

## 1. 메시지 → 원인 → 고치기
| # | 메시지 (첫 줄) | 원인 | 고치는 법 |
|---|---|---|---|
| E01 | `RuntimeError: mat1 and mat2 must have the same dtype, but got Double and Float` | 관측이 float64(numpy 기본, MuJoCo 관측도 float64)인데 신경망은 float32 | `torch.as_tensor(obs, dtype=torch.float32)` |
| E02 | `RuntimeError: addmm: mat1 and mat2 shapes cannot be multiplied (1x3 and 4x2)` | 입력 크기(3)와 첫 층 입력 크기(4)가 다름 | 첫 층을 `env.observation_space.shape[0]`으로 만들기. `print(x.shape)`로 확인 |
| E03 | `RuntimeError: element 0 of tensors does not require grad and does not have a grad_fn` | 손실을 `torch.no_grad()` 안에서 계산했거나, 기울기가 끊긴(`detach`) 값만으로 손실을 만듦 | 손실 계산은 `no_grad` 밖에서. 타깃만 `no_grad` |
| E04 | `RuntimeError: Trying to backward through the graph a second time ...` | 같은 계산 그래프로 `backward()`를 두 번(예: 옛 log_prob를 기울기 있는 채로 저장해 여러 epoch에 재사용) | 롤아웃 때 저장하는 값은 `no_grad` 안에서 만들거나 `.detach()`. 매 업데이트마다 순전파를 새로 |
| E05 | `RuntimeError: gather(): Expected dtype int32/int64 for index` | `gather`에 넣은 행동 인덱스가 float | `a.long()` (버퍼에 `np.int64`로 저장) |
| E06 | `RuntimeError: expected target dtype to be Long or Byte, but got Int` | `CrossEntropyLoss` 정답이 int32 | `y.long()` |
| E07 | `RuntimeError: expected target dtype to be Long or Byte, but got Float` | `CrossEntropyLoss` 정답(클래스 번호)이 float | `y.long()` (행동 복제에서 시연 행동 라벨) |
| E08 | `NameNotFound: Environment 'CartPol' doesn't exist. Did you mean: 'CartPole'?` | 환경 이름 오타 | 메시지가 맞는 이름을 알려 줌 |
| E09 | `VersionNotFound: Environment version 'v3' for environment 'CartPole' doesn't exist. It provides versioned environments: [ 'v0', 'v1' ].` | 없는 버전 | 메시지에 나온 버전으로(예: `CartPole-v1`, MuJoCo는 `-v5`) |
| E10 | `ResetNeeded: Cannot call env.step() before calling env.reset()` | `reset` 전에 `step` | 처음과 판이 끝날 때마다 `obs, _ = env.reset()` |
| E11 | `RuntimeError: a Tensor with 2 elements cannot be converted to Scalar` | 원소가 여러 개인 텐서에 `.item()` | 배치면 `.mean().item()` 또는 `.tolist()`, 행동 하나면 `[0]`으로 꺼낸 뒤 |
| E12 | `RuntimeError: Can't call numpy() on Tensor that requires grad. Use tensor.detach().numpy() instead.` | 기울기가 붙은 텐서를 numpy로 | `.detach().numpy()` 또는 `with torch.no_grad():` 안에서 |
| E13 | `RuntimeError: a leaf Variable that requires grad is being used in an in-place operation.` | 타깃망 Polyak 갱신을 `no_grad` 없이 제자리(`mul_`, `add_`)로 | `with torch.no_grad():` 안에서 하거나 `pt.data.mul_(…)` |
| E14 | `AssertionError: tensor(1) (<class 'torch.Tensor'>) invalid` | 이산 행동을 텐서 그대로 `env.step`에 넘김 | `env.step(a.item())` 또는 `int(a)` |
| E15 | `AssertionError: np.int64(5) (<class 'numpy.int64'>) invalid` | 이산 행동이 범위 밖(행동 수 2인데 5) | 출력층 크기를 `env.action_space.n`으로, argmax 결과 확인 |
| E16 | (오류 없음) 손실이 `-inf` 또는 `nan` | `log(0)` (예: 확률 0에 log) | 로그 안에 `+ 1e-12`, 확률은 `Categorical(logits=…)`로 계산, 학습률↓, 기울기 클리핑 |

## 2. 오류는 없는데 이상할 때
| 증상 | 확인할 것 |
|---|---|
| 리턴이 무작위 기준선과 똑같음 | 학습 루프가 실제로 `opt.step()`까지 도는지, 행동을 정책에서 뽑는지(계속 무작위로 고르고 있지 않은지) |
| 리턴이 기준선보다 낮음 | 보상 부호, 종료 처리(terminated만 미래 0), 행동 범위(연속이면 clip·tanh 스케일) |
| 연속 행동 PPO가 전혀 안 배움 | `log_prob(…).sum(-1)` 합산 여부, 버퍼에 자르기 전 행동 저장 여부 |
| SAC 정책이 안 변함 | `rsample()`인지, 정책 손실이 정책 옵티마이저로 업데이트되는지 |
| 손실이 갑자기 `nan` | E16, 학습률 과다, 보상 크기 과다(정규화) |
| 같은 시드인데 결과가 다름 | `random`, `numpy`, `torch` 시드 + `env.reset(seed=…)` + `env.action_space.seed(…)` |
| 학습은 좋은데 평가가 나쁨 | 평가 때 탐험 끄기(argmax / 평균 행동), `model.eval()` |

## 3. 디버깅 순서 (막혔을 때)
1. 오류 메시지 **마지막 줄**과 **내 코드 줄 번호**를 본다.
2. 문제 줄 바로 앞에서 `print(x.shape, x.dtype)`로 모양·자료형을 찍는다.
3. 1스텝만 돌려 본다(`env.step` 한 번, 업데이트 한 번).
4. 학습 스텝을 아주 작게(예: 1천) 해서 끝까지 도는지 먼저 확인한다.
5. 그래도 모르면 메시지 첫 줄을 그대로 검색해 본다.
